## データ結合フロー

```
[1] EJ CSV読込 (ASPKakouDenpyo.csv)
     ↓ (客先コードでLEFT JOIN)
[2] i-reporter客先マスタ結合 (view_mst_custom_record)
     ↓ (伝票Ｎｏ=SLIP_NOでLEFT JOIN)
[3] KRD工程バージョン結合 (DATA_ASP2_PUT)
     ↓ (加工部番=FINAL_ITEM_CODE + VERSIONでLEFT JOIN)
[4] KRDプロセスコード結合 (MSTR_PROCODESTR)
     ↓ (加工部番=SETU_FでLEFT JOIN)
[5] KRD図番情報結合 (DATA_KOUTEIZUKAN)
     ↓ (加工部番=FIN_CODEでLEFT JOIN)
[6] KRDメッキ情報結合 (MSTR_METAL)
     ↓
[7] genpinhyoテーブルに保存 (REPLACE INTO)
     ↓
[8] buhin_irepo_mst更新 (INSERT ON CONFLICT DO NOTHING)
     ↓
[9] delete_mst初期化 (INSERT ON CONFLICT DO NOTHING)
     ↓
[10] 削除フラグ更新処理
      - 当月～翌々々月のデータを抽出
      - 新CSVデータと比較して削除データを検知
      - 削除flgを更新 (UPDATE delete_mst)
```

## 特記事項

### データ加工処理

| 項目 | 加工内容 | 実装箇所 |
|---|---|---|
| 月次 | 6文字の場合は末尾に"_"を追加 | 252-253行目 |
| 吋・G | 整数値の場合は小数点以下を削除 | 241-250行目 |
| 完成部番・組立番号・機種・国名・客先名 | 全角スペースを半角スペースに変換 | 254-258行目 |
| 全項目 | NaN/Noneを空文字列に変換 | 259行目 |

### 削除フラグ更新ロジック (ADD_20241124～)

**対象期間**: 当月～翌々々月 (4ヶ月分)

**更新処理**:
1. genpinhyoテーブルとdelete_mstをロット番号で結合
2. 対象期間でフィルタリング
3. 新CSVデータ(mdf)と比較
4. 新CSVに存在しない → 削除flg=1
5. 新CSVに存在する → 削除flg=0
6. 削除対象がある場合はCSV出力 (`EJ削除flg_on_YYYYMMDDHHMMSS.csv`)

### QRコード生成ロジック

**QRコードレイアウト区分による分岐**:

| 区分 | QRコード内容 | 用途 |
|---|---|---|
| 0 | `jp.co.cimtops.ireporter.openreport:repid={帳票発行ID}` | i-Reporter連携型 |
| 1 | `{ロット番号},{月次},{組立番号},...` (カンマ区切り) | 旧レイアウト |
| 2 | エラー画像 (`template\err.png`) | 新規部品名検知・未設定 |

**特殊処理** (ADD_20241108):
- 完成部番に `-111`, `-404`, `-102` を含む場合
- かつ必要数が2個以上の場合
- → 必要数分のQRコードを生成し、"1/3", "2/3", "3/3"形式で表示

```sql
    ロット番号 TEXT PRIMARY KEY,

    G TEXT,

    部品名 TEXT,

    国名 TEXT,
    B1図番 TEXT,
    B2図番 TEXT,
    F1図番 TEXT,
    F2図番 TEXT,
    L図番 TEXT,
    R図番 TEXT,
    C図番 TEXT,
    組立開始日 TEXT,
    梱包開始日 TEXT,
    指定納期 TEXT,
    必要数 TEXT,
    SKDK TEXT,
    工程 TEXT,
    工程VERSION TEXT,
    ﾒｯｷ TEXT,
```

### buhin_irepo_mstテーブル (部品管理マスタ)

```sql
CREATE TABLE IF NOT EXISTS buhin_irepo_mst(
    部品名 TEXT PRIMARY KEY,
```

```sql
CREATE TABLE IF NOT EXISTS delete_mst(
```
