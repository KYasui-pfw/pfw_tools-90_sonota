# 本番切り替え時のデータ補正手順（genpinhyo_web）

現品票アプリの外で行うデータの補正を、本番切り替えの当日に行う手順。
アプリに組み込まず、`tools/` のスクリプトを人が1回だけ実行する。

- 作成: 2026-10-26
- 実行する人: 利用者（AI は実行しない）
- かかる時間: 補正だけなら10分ほど（DB のコピー時間は別）

## 0. この手順でやること

| # | 対象 | スクリプト | 内容 |
|---|---|---|---|
| A | genpinhyo.db | `tools/migrate_genpinhyo_db.py` | 印刷履歴などを表ごと JSON で貯めていた `output_history`（約1GB）を zip に退避し、印刷履歴を `print_history` に移す。`excluded_lots` を作り直し、VACUUM と WAL 化をする。**1.4GB → 30MB ほど** |
| B | checksheet.db | `tools/clean_checksheet_db.py` | 工程順が数字でない壊れた行（F始まりの伝票番号が入った行・`MCW` だけの行。約6,000行）と、それにぶら下がる空のチェック項目を消す |

- どちらも**実行前にバックアップを自動で取る**。消した中身も zip・CSV に残る。
- どちらも**何度実行しても壊れない**。2回目以降は、終わった部分を飛ばす。
- どちらも `--dry-run` を付けると、件数を表示するだけで何も変えない。

⚠ 件数は、この手順書を作った日（2026-10-26）の写しで試したときの値。
  当日は旧アプリ（`D:\py\genpin_check`）が動き続けた分だけ増える。大きく違わなければ問題ない。

## 1. 事前の準備（前日までに）

1. 本番サーバーの `genpinhyo_web` に、最新のプログラムを置く（`genpin/`・`tools/`・`template/add_template.xlsx` を含む）。
2. 本番サーバーの Python で、次の1行が通ることを確かめる（旧アプリと同じ Python でよい）。
   ```
   cd <genpinhyo_web の場所>
   python -c "from genpin import config, db, update, listing, tag_excel, conmas; print('OK')"
   ```
3. ディスクの空きを確かめる。**genpinhyo.db の大きさの3倍以上**（目安 5GB）。
   移行前のバックアップ（同じ大きさ）と VACUUM の作業領域に使う。

## 2. 当日：止める

次のものを止める。止めないと、補正の途中で書き込まれてバックアップと食い違う。

- [ ] 現品票の画面（旧 `genpin_check` の Streamlit。port 8502）
- [ ] チェック項目入力（check_input。port 8506）
- [ ] タスクスケジューラの `create_report.py`・`dbupdate.py`（「無効」にする）
- [ ] i-Reporter からの呼び出し（`75_genpin展開` の3本）は止められないので、**現場で i-Reporter を使わない時間帯**に行う

## 3. 当日：本番の DB を持ってくる

旧アプリの DB を、`genpinhyo_web\Database\` に上書きでコピーする。

| コピー元 | コピー先 |
|---|---|
| `D:\py\genpin_check\Database\genpinhyo.db` | `<genpinhyo_web>\Database\genpinhyo.db` |
| `D:\py\genpin_check\Database\checksheet.db` | `<genpinhyo_web>\Database\checksheet.db` |
| `D:\py\genpin_check\mapping_data.db`（95 管理画面用） | `<genpinhyo_web>\mapping_data.db` |

⚠ 旧アプリ側のファイルは**消さない・動かさない**（戻すときに使う）。

## 4. 当日：補正 A（genpinhyo.db）

```
cd <genpinhyo_web の場所>
python tools/migrate_genpinhyo_db.py --dry-run
```

表示の目安（2026-10-26 の写し）:
```
対象: ...\Database\genpinhyo.db（1,386MB）
  output_history「EJ削除flg_on」: 7,797件・951MB
  output_history「履歴」: 2,729件・23MB
  → print_history に移す行: 49,690行
--dry-run なので何も変えていません。
```

問題なければ本番を実行する（約2分）:
```
python tools/migrate_genpinhyo_db.py
```

終わりの表示の目安:
```
7. 完了: ...\Database\genpinhyo.db（28MB）
```

できるもの:
- `Database\backup\before_migrate_YYYYMMDDhhmmss.db` … 移行前の丸ごとのバックアップ
- `Database\archive\output_history_YYYYMMDDhhmmss.zip` … 退避した記録（約70MB）

## 5. 当日：補正 B（checksheet.db）

```
python tools/clean_checksheet_db.py --dry-run
```

表示の目安:
```
kouteizuban の壊れた行: 6,034行（全体 19,908行）
それにぶら下がる zubancheck: 6,034行（チェック項目が入っている行 0行）
--dry-run なので何も変えていません。
```

⚠ 「チェック項目が入っている行」が **0 でないときは実行しない**（スクリプトも止まる）。
  その行を確かめてから判断する。

問題なければ本番を実行する:
```
python tools/clean_checksheet_db.py
```

できるもの:
- `Database\backup\before_clean_YYYYMMDDhhmmss_checksheet.db` … 掃除前の丸ごとのバックアップ
- `Database\backup\YYYYMMDDhhmmss_clean_deleted_kouteizuban.csv` … 消した行の一覧

## 6. 当日：確かめる

```
python -c "import sqlite3; c=sqlite3.connect('Database/genpinhyo.db'); print(c.execute('pragma journal_mode').fetchone(), c.execute('select count(*) from genpinhyo').fetchone(), c.execute('select count(*) from print_history').fetchone())"
python -c "import sqlite3; c=sqlite3.connect('Database/checksheet.db'); print(c.execute(\"select count(*) from kouteizuban where typeof(工程順)<>'integer'\").fetchone(), c.execute('select count(*) from kouteizuban').fetchone())"
python -m unittest discover tests
```

- 1行目: `('wal',)`・genpinhyo の件数（補正前と同じ）・print_history の件数（4. の「移す行」と同じ）
- 2行目: 壊れた行が `(0,)`、全体が補正前から 6,034行ほど減っている
- 3行目: `OK`

## 7. 切り替えたあとに起きること（異常ではない）

新しいアプリで最初にデータ更新が走ったときに、次のことが起きる。

| 起きること | 件数の目安 | 理由 |
|---|---|---|
| 削除扱いになるロット | 約3,940件 | 旧の夜間処理が、払出先49・60の伝票を誤って戻していた。本来の状態（一覧に出さない）になる。**2回目以降はほぼ0件** |
| 工程が新たに埋まるロット | 約950件 | `478-409TA33` などの部番を二重に変換して引けていなかった不具合が直る |
| 必要数の表記 | 書き直した行 | `1.0` → `1`。古い行は `1.0` のまま残るが、読む側で吸収している |
| check_input の最初の同期で消える工程 | 1件 | `954-502JA30` VER2 工程順5（品目工程マスタから消えている）。入力済みのチェック項目が2件あるので、必要なら `Database\backup\*_mastersync_deleted_*.csv` から確かめる |

## 8. 戻すとき

補正だけを戻す（新しいアプリは使い続ける）:
1. 新しいアプリを止める（2. と同じ）
2. `Database\backup\before_migrate_*.db` を `Database\genpinhyo.db` に、
   `Database\backup\before_clean_*_checksheet.db` を `Database\checksheet.db` に上書きでコピーする
3. ⚠ `genpinhyo.db-wal`・`genpinhyo.db-shm` が残っていたら消してから起動する（WAL の作業ファイル。古い DB に混ざると壊れる）

旧アプリに戻す:
- 旧 `D:\py\genpin_check` は触っていないので、旧アプリを起動し直し、タスクスケジューラも旧側に戻せばよい。

## 9. この手順以外に切り替えで要ること（データ補正ではないもの）

- i-Reporter のスクリプト（`90_tools/75_genpin展開` の `check_tenkai.py`・`check_koushin.py`・`header_koushin.py`）は
  `d:\py\genpin_check\database\` を直接読んでいる。新しい置き場所に向け直す
- Django の加工スケジュール（`apps/machining_schedule`）と esrv10 の写し（`apps/schedule_inquiry/esrv10_copy`）が
  `D:\py\genpin_check\Database\checksheet.db` を読んでいる。新しい置き場所に向け直す
- タスクスケジューラの `create_report.py`・`dbupdate.py` の場所を新しい置き場所に変える（ファイル名は同じ）
- 起動用の bat（`Genpin_Start.bat`・`Check_input_start.bat`）の置き場所
