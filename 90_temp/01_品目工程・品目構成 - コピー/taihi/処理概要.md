# 00_extract_krd_data.py 処理概要

## 概要
KRDデータベース（MySQL）とEJシステム（Oracle）からデータを抽出し、品目コードの桁数統一処理を行って、マシニング課管理工程マスタとEJシステムマスタを作成するスクリプトです。

## 処理フロー

### 1. KRDデータベース抽出（指示12）
**目的**: 製造工程管理データから品目コードを抽出

**処理内容**:
```sql
SELECT DISTINCT FINAL_ITEM_CODE
FROM DATA_RES_CAPA
WHERE FINAL_ITEM_CODE IS NOT NULL 
  AND FINAL_ITEM_CODE != ''
ORDER BY FINAL_ITEM_CODE
```

**出力**: `01_krd全件データ.csv`
- 約3,233行の品目コードリスト
- 重複なしの一意な値のみ

### 2. 品目コード桁数修正処理（指示13）
**目的**: 品目コードの表記揺れを統一

**修正ルール**:
- **下2桁が数字の場合**: 末尾に`0`を追加
  - 例: `100-501NA26` → `100-501NA260`
- **小数点1桁の場合**: 100倍変換+桁移動処理
  - 例: `100-501NA5.5` → `100-501NA055` (550→055の変換)
- **その他**: 変更なし

**出力**: `02_krd桁数修正データ.csv`

### 3. KRDデータ統合（指示14）
**目的**: 元データと修正データを統合して完全なマスタを作成

**処理手順**:
1. `01_krd全件データ.csv`と`02_krd桁数修正データ.csv`を読み込み
2. 縦結合（pd.concat）
3. 重複データの除去（drop_duplicates）

**出力**: `03_マシニング課管理工程.csv`

### 4. EJシステムデータ抽出（指示17）
**目的**: EJシステム（Oracle）からPRODUCT_TYP=6,7,8の品目データを抽出

**処理内容**:
```sql
SELECT ITEM_CD, PRODUCT_TYP
FROM EXPJ2.M_ITEM
WHERE ITEM_CD NOT LIKE '!%'
  AND PRODUCT_TYP IN (6, 7, 8)
ORDER BY ITEM_CD
```

**出力**: `04_EJ678.csv`

# 01_integrated_process.py 処理概要（最新版）

## 概要
前工程横展開データを統合・加工し、品目構成・品目工程マスタ作成用のデータに整形するスクリプトです。EJシステム（04_EJ678.csv）とマシニング課管理工程（03_マシニング課管理工程.csv）との突合により、最終的な処理対象を絞り込み、横展開形式から縦展開形式への変換を行います。

## 処理フロー

### **ステップ1: CSVファイルの結合**
**目的**: 3つの前工程横展開ファイルを縦結合

**処理**:
1. 以下3ファイルを縦結合:
   - `前工程横展開.csv`
   - `前工程横展開(I).csv`
   - `前工程横展開(C).csv` ← 直接使用（指示16対応）
2. **区分コード保持**: 1列目（区分コード）を削除せず維持
3. 21列目以降（前工程6より後）を削除（区分コード保持のため+1列）
4. **出力**: `06_combined_前工程横展開.csv` (22,339行 × 20列)

### **ステップ1.5: EJシステムとマシニング課管理工程突合**
**目的**: 除外対象データとの突合により、最終的な処理対象を決定

**処理**:
1. `04_EJ678.csv`からITEM_CDとPRODUCT_TYP（6,7,8）を取得
2. `03_マシニング課管理工程.csv`からFINAL_ITEM_CODEを取得（6,216件）
3. `06_combined_前工程横展開.csv`の完成部番（2列目）と上記2つを突合
4. 分離結果:
   - **一致（対象外）** → `07_matched_前工程横展開.csv` (5,483行)
   - **不一致（処理対象）** → `08_unmatched_前工程横展開.csv` (16,857行)
5. **重要**: 後続処理は`08_unmatched`（一致しなかったデータ）を使用

### **ステップ2: MA-プレフィックス分離**
**目的**: 前工程データをMA-で始まるかどうかで分類

**処理**:
1. `08_unmatched_前工程横展開.csv`を読み込み（16,856行）
2. 各行で前工程1～6の中で最も右（大きい番号）の非空白データを特定
   - **前工程列位置**: `[4,7,10,13,16,19]`（区分コード保持のため+1調整）
3. そのデータがMA-で始まるかで分離:
   - **MA-で始まる** → `09_MA_prefix_data.csv` (10,383行)
   - **MA-で始まらない** → `10_non_MA_prefix_data.csv` (6,473行)

### **ステップ3: データ展開処理**
**目的**: 横展開されたデータを縦展開形式に変換

**処理**:
1. `09_MA_prefix_data.csv`と`10_non_MA_prefix_data.csv`を個別処理
2. 各行の前工程セット（単位数分子・分母・前工程）を6→1の順で縦展開
   - **完成部番取得**: `row.iloc[1]`（区分コード保持のため2列目）
   - **列インデックス**: セットN → `[3*N-1, 3*N, 3*N+1]`（区分コード保持調整）
3. ヘッダー付きCSVに変換:
   - `No,完成部番,単位数分子,単位数分母,前工程`
4. 出力:
   - `11_MA_expanded_data.csv` (62,298行)
   - `12_non_MA_expanded_data.csv` (38,838行)

### **ステップ4: 前工程空白削除と最終分離**
**目的**: 空白行削除とMA-プレフィックスによる最終分離

**処理**:
#### 4-1: MA拡張データの処理
1. `11_MA_expanded_data.csv`から前工程空白行を削除（62,298行 → 21,046行）
2. 残ったデータをMA-プレフィックスで分離:
   - **MA-で始まる** → `13_品目構成work.csv` (10,383行)
   - **MA-で始まらない** → `14_品目工程work.csv` (10,663行)

#### 4-2: non-MA拡張データの処理
1. `12_non_MA_expanded_data.csv`から前工程空白行を削除（38,838行 → 12,535行）
2. ファイルを上書き更新

## 主要関数

### `expand_data(work_dir, input_filename, output_filename)`
- **機能**: 横展開データを縦展開形式に変換
- **処理**: 前工程セット（単位数分子・分母・前工程）を6→1の順でレコード化
- **区分コード対応**: 完成部番を`row.iloc[1]`から取得、列インデックス調整

### `process_step4_ma_data(work_dir, input_filename)`
- **機能**: MA拡張データの空白行削除と最終分離
- **処理**: 前工程空白行削除→MA-プレフィックス判定→分離出力

### `process_step4_non_ma_data(work_dir, input_filename)`
- **機能**: non-MA拡張データの空白行削除
- **処理**: 前工程空白行削除→上書き更新

# 03_create_item_process_master.py 処理概要

## 概要
14_品目工程work.csvを読み込んで、M0840品目工程マスタのレイアウトでCSV出力するスクリプトです。EJシステム（Oracle）との連携により、SRCD（仕入先コード）とLDTIME（リードタイム）を動的に取得し、M0410工程マスタとの整合性チェックを行います。

## M0840品目工程マスタ出力ルール（最新版）

### 基本マッピング
1. **HMCD**：14_品目工程work.csvの「完成部番」
2. **SEQ**：同じHMCDの場合、1単位で連番（1,2,3,...）
3. **KTSEQ**：同じHMCDの場合、10単位で連番（10,20,30,...）
4. **KTCD**：前工程の最初のハイフンまでの文字列（存在チェック付き）
   - M0410工程マスタに存在しない場合：「KTCD（無）」形式で出力
5. **SRCD**：EJ M_PUCH_UNIT_COSTテーブルから取得（前工程をキーとして）
   - 一致しない場合：「無し」
   - 複数一致の場合：EFF_PHASE_IN_DATEが最新の行を使用
6. **LDTIME**：EJ M_ITEMテーブルのPUCH_FIXED_LT（完成部番をキーとして）

### 固定値・条件値設定（指示22対応）
- **SGNCD**：空欄（""）
- **DDTIME**：0
- **SGTIME**：0
- **SRPRICE**：0
- **CSBCD**："13"
- **SUPCLSCD**：KTCDが"AO"で始まる場合（"AO（無）"を含む）は"6"、それ以外は"5"
- **SUPCD**：空欄
- **RCVTSTKBN**："1"
- **RCVCHKKBN**："1"
- **INSTID, INSTDT, UPDTID, UPDTDT**：空欄

## EJシステム連携処理

### 接続設定
- **接続先**：172.17.107.102:1521/EXPJ
- **ユーザー**：EXPJ2/EXPJ2
- **ドライバー**：cx_Oracle

### SRCD取得処理
```sql
SELECT ITEM_CD, VEND_CD, EFF_PHASE_IN_DATE
FROM EXPJ2.M_PUCH_UNIT_COST
ORDER BY ITEM_CD, EFF_PHASE_IN_DATE DESC
```
- **キー**：14_品目工程work.csvの「前工程」
- **取得値**：VEND_CD
- **重複処理**：EFF_PHASE_IN_DATEの最新日付を優先

### LDTIME取得処理
```sql
SELECT ITEM_CD, PUCH_FIXED_LT
FROM EXPJ2.M_ITEM
```
- **キー**：14_品目工程work.csvの「完成部番」
- **取得値**：PUCH_FIXED_LT

## 工程マスタ整合性チェック
- **参照ファイル**：input/M0410_工程マスタ.csv
- **チェック対象**：KTCD（工程コード）
- **処理**：M0410に存在しないKTCDに「（無）」を付与

## 処理統計出力
- 処理対象の品目数（HMCD）
- 総工程数
- HMCDごとの工程数（上位10件）
- SRCD・LDTIME取得状況

## 出力ファイル
- **ファイル名**：output/M0840_品目工程マスタ.csv
- **エンコーディング**：UTF-8-SIG
- **ヘッダー**：あり

# 11_購買課確認用.py 処理概要

## 概要
品目工程・品目構成処理パイプラインの品質保証段階として、non-MA処理対象データの検証を行うスクリプトです。担当者情報の付与、工程コード抽出、M0410工程マスタとの整合性確認により、後工程での処理適格性を判定します。

## 処理フロー

### **ステップ1: 入力ファイル読み込み**
**目的**: 検証に必要な全データの取得

**処理**:
1. `work/10_non_MA_prefix_data.csv`の読み込み（6,473行）
2. `input/担当者.csv`の読み込み（複数エンコーディング対応）
3. `input/M0410_工程マスタ.csv`の読み込み（工程コード整合性チェック用）

### **ステップ2: 担当者名項目追加**
**目的**: 区分コードに対応する担当者名の付与

**処理**:
1. 担当者.csvから`SUPCD`→`SUPNM`の辞書作成
2. 区分コードの右に「担当者名」列を挿入
3. 区分コード突合による担当者名マッピング

### **ステップ3: 最大前工程項目特定・工程コード抽出**
**目的**: 各レコードの代表工程コードを特定

**処理**:
1. 前工程1～6の中で空欄でない最も番号が大きい項目を特定
2. 特定した前工程値を「最大前工程項目」として記録
3. 最初のハイフンまでの文字列を「工程コード」として抽出

### **ステップ4: M0410工程マスタ突合・振り分け**
**目的**: 工程マスタ適格性による処理可否判定

**処理**:
1. M0410工程マスタの有効KTCD集合を作成
2. 抽出した工程コードとの突合実行
3. 振り分け結果:
   - **一致データ**: 工程マスタ登録済み（処理適格）
   - **不一致データ**: 工程マスタ未登録（要確認）

### **ステップ5: 結果出力**
**目的**: 検証結果の可視化と後続確認準備

**出力ファイル**:
- `kensyou/購買課確認用_工程マスタ一致.csv`（区分コード昇順）
- `kensyou/購買課確認用_工程マスタ不一致.csv`（区分コード昇順）

## 主要機能

### `main()`
- **機能**: 全体処理の統括実行
- **処理**: 5段階の検証プロセスの順次実行
- **エラーハンドリング**: ファイル存在確認、エンコーディング自動選択

### エンコーディング自動選択
- **対応形式**: UTF-8-SIG、Shift_JIS、CP932
- **処理**: 複数エンコーディングの順次試行による読み込み成功保証

### 統計情報出力
- 総データ数と振り分け割合
- 工程コード出現頻度（上位10件）
- M0410工程マスタ適合状況
- 出力データサンプル表示
