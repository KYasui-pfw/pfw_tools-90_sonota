# 00_extract_krd_data.py 処理概要

## 概要
KRDデータベース（MySQL）とEJシステム（Oracle）からデータを抽出し、品目コードの桁数統一処理を行って、マシニング課管理工程マスタとEJシステムマスタを作成するスクリプトです。

## 処理フロー

### 1. KRDデータベース抽出（指示12）
**目的**: 製造工程管理データから品目コードを抽出

**処理内容**:
```sql
SELECT DISTINCT FINAL_ITEM_CODE
FROM DATA_RES_CAPA
WHERE FINAL_ITEM_CODE IS NOT NULL 
  AND FINAL_ITEM_CODE != ''
ORDER BY FINAL_ITEM_CODE
```

**出力**: `01_krd全件データ.csv`
- 約3,233行の品目コードリスト
- 重複なしの一意な値のみ

### 2. 品目コード桁数修正処理（指示13）
**目的**: 品目コードの表記揺れを統一

**修正ルール**:
- **下2桁が数字の場合**: 末尾に`0`を追加
  - 例: `100-501NA26` → `100-501NA260`
- **小数点1桁の場合**: 100倍変換+桁移動処理
  - 例: `100-501NA5.5` → `100-501NA055` (550→055の変換)
- **その他**: 変更なし

**出力**: `02_krd桁数修正データ.csv`

### 3. KRDデータ統合（指示14）
**目的**: 元データと修正データを統合して完全なマスタを作成

**処理手順**:
1. `01_krd全件データ.csv`と`02_krd桁数修正データ.csv`を読み込み
2. 縦結合（pd.concat）
3. 重複データの除去（drop_duplicates）

**出力**: `03_マシニング課管理工程.csv`

### 4. EJシステムデータ抽出（指示17）
**目的**: EJシステム（Oracle）からPRODUCT_TYP=6,7,8の品目データを抽出

**処理内容**:
```sql
SELECT ITEM_CD, PRODUCT_TYP
FROM EXPJ2.M_ITEM
WHERE ITEM_CD NOT LIKE '!%'
  AND PRODUCT_TYP IN (6, 7, 8)
ORDER BY ITEM_CD
```

**出力**: `04_EJ678.csv`

# 01_integrated_process.py 処理概要（最新版）

## 概要
前工程横展開データを統合・加工し、品目構成・品目工程マスタ作成用のデータに整形するスクリプトです。EJシステム（04_EJ678.csv）とマシニング課管理工程（03_マシニング課管理工程.csv）との突合により、最終的な処理対象を絞り込み、横展開形式から縦展開形式への変換を行います。

## 処理フロー

### **ステップ1: CSVファイルの結合**
**目的**: 3つの前工程横展開ファイルを縦結合

**処理**:
1. 以下3ファイルを縦結合:
   - `前工程横展開.csv`
   - `前工程横展開(I).csv`
   - `前工程横展開(C).csv` ← 直接使用（指示16対応）
2. **区分コード保持**: 1列目（区分コード）を削除せず維持
3. 21列目以降（前工程6より後）を削除（区分コード保持のため+1列）
4. **出力**: `06_combined_前工程横展開.csv` (22,339行 × 20列)

### **ステップ1.5: EJシステムとマシニング課管理工程突合**
**目的**: 除外対象データとの突合により、最終的な処理対象を決定

**処理**:
1. `04_EJ678.csv`からITEM_CDとPRODUCT_TYP（6,7,8）を取得
2. `03_マシニング課管理工程.csv`からFINAL_ITEM_CODEを取得（6,216件）
3. `06_combined_前工程横展開.csv`の完成部番（2列目）と上記2つを突合
4. 分離結果:
   - **一致（対象外）** → `07_matched_前工程横展開.csv` (5,483行)
   - **不一致（処理対象）** → `08_unmatched_前工程横展開.csv` (16,857行)
5. **重要**: 後続処理は`08_unmatched`（一致しなかったデータ）を使用

### **ステップ2: MA-プレフィックス分離**
**目的**: 前工程データをMA-で始まるかどうかで分類

**処理**:
1. `08_unmatched_前工程横展開.csv`を読み込み（16,856行）
2. 各行で前工程1～6の中で最も右（大きい番号）の非空白データを特定
   - **前工程列位置**: `[4,7,10,13,16,19]`（区分コード保持のため+1調整）
3. そのデータがMA-で始まるかで分離:
   - **MA-で始まる** → `09_MA_prefix_data.csv` (10,383行)
   - **MA-で始まらない** → `10_non_MA_prefix_data.csv` (6,473行)

### **ステップ3: データ展開処理**
**目的**: 横展開されたデータを縦展開形式に変換

**処理**:
1. `09_MA_prefix_data.csv`と`10_non_MA_prefix_data.csv`を個別処理
2. 各行の前工程セット（単位数分子・分母・前工程）を6→1の順で縦展開
   - **完成部番取得**: `row.iloc[1]`（区分コード保持のため2列目）
   - **列インデックス**: セットN → `[3*N-1, 3*N, 3*N+1]`（区分コード保持調整）
3. ヘッダー付きCSVに変換:
   - `No,完成部番,単位数分子,単位数分母,前工程`
4. 出力:
   - `11_MA_expanded_data.csv` (62,298行)
   - `12_non_MA_expanded_data.csv` (38,838行)

### **ステップ4: 前工程空白削除と最終分離**
**目的**: 空白行削除とMA-プレフィックスによる最終分離

**処理**:
#### 4-1: MA拡張データの処理
1. `11_MA_expanded_data.csv`から前工程空白行を削除（62,298行 → 21,046行）
2. 残ったデータをMA-プレフィックスで分離:
   - **MA-で始まる** → `13_品目構成work.csv` (10,383行)
   - **MA-で始まらない** → `14_品目工程work.csv` (10,663行)

#### 4-2: non-MA拡張データの処理
1. `12_non_MA_expanded_data.csv`から前工程空白行を削除（38,838行 → 12,535行）
2. ファイルを上書き更新

## 主要関数

### `expand_data(work_dir, input_filename, output_filename)`
- **機能**: 横展開データを縦展開形式に変換
- **処理**: 前工程セット（単位数分子・分母・前工程）を6→1の順でレコード化
- **区分コード対応**: 完成部番を`row.iloc[1]`から取得、列インデックス調整

### `process_step4_ma_data(work_dir, input_filename)`
- **機能**: MA拡張データの空白行削除と最終分離
- **処理**: 前工程空白行削除→MA-プレフィックス判定→分離出力

### `process_step4_non_ma_data(work_dir, input_filename)`
- **機能**: non-MA拡張データの空白行削除
- **処理**: 前工程空白行削除→上書き更新

## フローチャート説明

### データの流れ
1. **入力段階**: 3つの前工程横展開ファイルと2つの突合用ファイル
2. **結合・絞り込み段階**: ファイル結合後、CAFIN/マシニング課管理工程との突合で処理対象を絞り込み
3. **分離・変換段階**: MA-プレフィックス分離後、横展開から縦展開形式に変換
4. **最終処理段階**: 空白行削除と最終分離により、品目構成・品目工程マスタを出力

### 特徴
- **ヘッダー統一**: 全ファイルで統一されたヘッダー形式
- **データ整合性**: 各ステップで行数の整合性を確保
- **処理の透明性**: 中間ファイルを保持し、各段階の処理結果を確認可能
- **効率的な絞り込み**: 早期段階で対象外データを除外し、処理効率を向上
