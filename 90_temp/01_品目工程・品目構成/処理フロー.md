# 品目工程・品目構成マスタ作成処理フロー

## 概要
この処理は、製造業の生産管理システムで使用する「品目工程マスタ」と「品目構成マスタ」を作成するためのデータ変換処理です。複数のデータベースシステムからデータを取得・統合し、最終的に標準的なマスタデータ形式に変換します。

## インプットデータ一覧

### CSVファイル（inputフォルダ）
| ファイル名 | 説明 |
|-----------|------|
| `前工程横展開.csv` | EJより出力されたファイル |
| `前工程横展開(I).csv` | EJより出力されたファイル |
| `前工程横展開(C).csv` | EJより出力されたファイル|
| `M0410_工程マスタ.csv` | rBOMで使用する工程コードの一覧 |
| `担当者.csv` | 担当者コードと担当者名の変換テーブル |

### データベーステーブル
| データベース | テーブル名 | 説明 |
|-------------|-----------|------|
| KRD（MySQL） | `DATA_RES_CAPA` | マシニング課管理データ |
| EJ（Oracle） | `M_ITEM` | EJ品目テーブル |
| EJ（Oracle） | `M_PUCH_UNIT_COST` | EJ購入単価 |

## 処理の全体流れ
```
データ抽出 → データ統合・変換 → 構成マスタ作成 → 工程マスタ作成
    ↓            ↓              ↓            ↓
00_extract   01_integrated   02_create    03_create
_krd_data.py _process.py     _item_       _item_
                           composition   process
                           _master.py    _master.py
```

## ステップ1: データ抽出処理
**スクリプト名**: `00_extract_krd_data.py`

### 入力データ
- **KRDデータベース**: 製造実績データ（DATA_RES_CAPA テーブル）
- **EJデータベース**: 品目マスタデータ（M_ITEM テーブル）

### 処理1-1: KRDデータベースからの工程データ抽出
**処理内容**:
- DATA_RES_CAPAテーブルから外注工程とマシニング課管理工程のデータを抽出
- FINAL_ITEM_CODEの重複を除去

**出力**: `01_krd全件データ.csv`

### 処理1-2: 品目コードの桁数修正
**処理内容**:
- 品目コードの下2桁が数字の場合、末尾に0を追加（例：100-501NA26 → 100-501NA260）
- 小数点1桁の場合、100倍して3桁の先頭に0を移動（例：100-501NA5.5 → 100-501NA055）

**出力**: `02_krd桁数修正データ.csv`

### 処理1-3: KRDデータの統合
**処理内容**:
- `01_krd全件データ.csv`と`02_krd桁数修正データ.csv`を縦に結合
- 重複データを除去

**出力**: `03_マシニング課管理工程.csv`

### 処理1-4: EJシステムからの品目データ取得
**処理内容**:
- M_ITEMテーブルから以下条件でデータを抽出:
  - 品目コードが"!"で始まらない
  - 製品区分が6、7、8のいずれか

**出力**: `04_EJ678.csv`

## ステップ2: データ統合・変換処理
**スクリプト名**: `01_integrated_process.py`

### 入力データ
- `前工程横展開.csv`, `前工程横展開(I).csv`, `前工程横展開(C).csv`
- `03_マシニング課管理工程.csv` (ステップ1で作成)
- `04_EJ678.csv` (ステップ1で作成)

### 処理2-1: 前工程データの統合
**処理内容**:
- 3つのファイルを縦に結合:
  - `前工程横展開.csv`
  - `前工程横展開(I).csv` 
  - `前工程横展開(C).csv`
- ヘッダー重複を除去、18列目以降を削除

**出力**: `06_combined_前工程横展開.csv`

### 処理2-2: EJ678データとの突合・分類
**処理内容**:
- `06_combined_前工程横展開.csv`を以下で分類:
  - `04_EJ678.csv`のITEM_CDとの突合結果
  - `03_マシニング課管理工程.csv`との突合結果
  - 最右の前工程が"SKD"、"SUJ"の場合の特別処理
  - 完成部番が"TS-"で始まるデータの特別処理

**出力**:
- `07_matched_前工程横展開.csv` (マッチしたデータ + 処理対象外)
- `08_unmatched_前工程横展開.csv` (処理対象データ)

### 処理2-3: MA prefix判定による分離
**処理内容**:
- `08_unmatched_前工程横展開.csv`の最右の前工程で判定:
  - "MA-"で始まる場合と始まらない場合で分離
- 例外処理:
  - 前工程1が"AO-"で始まり前工程2が空欄 → MA側
  - 前工程1が"PEFIN-"で始まり前工程2が非空欄、前工程3が空欄 → MA側
  - 特定品目（K-18405B等4品目）→ non-MA側

**出力**:
- `09_MA_prefix_data.csv`
- `10_non_MA_prefix_data.csv`

### 処理2-4: データの展開変換
**処理内容**:
- 各ファイルの前工程1～6を1行ずつに展開
- 工程順序を6→1の順に並び替え
- ヘッダー: No, 完成部番, 単位数分子, 単位数分母, 前工程

**出力**:
- `11_MA_expanded_data.csv`
- `12_non_MA_expanded_data.csv`

### 処理2-5: 最終データの分離
**処理内容**:
- 前工程が空欄の行を削除
- `11_MA_expanded_data.csv`を前工程の"MA-"開始で分離:
  - "MA-"で始まる → 品目構成データ
  - "MA-"で始まらない → 品目工程データ
- 例外処理: PEFIN関連の特別振り分け

**出力**:
- `13_品目構成work.csv` (構成マスタの元データ)
- `14_品目工程work.csv` (工程マスタの元データ)

## ステップ3: 品目構成マスタ作成
**スクリプト名**: `02_create_item_composition_master.py`

### 入力データ
- `13_品目構成work.csv` (ステップ2で作成)

### 処理3-1: M0850レイアウトへの変換
**処理内容**:
- 完成部番 → OYAHMCD（親品目コード）
- 前工程 → KOHMCD（子品目コード）
- 単位数分子 → KOQTY（子品目数量）
- 単位数分母 → OYAQTY（親品目数量）
- 固定値設定: SEQ=1, STRNO=1, OYAREVNO=1, STRSEQ=1, SHAPEQTY=1, OYAQTYKBN=1, HASUKBN=1, VALFLG=1, VALDEC=0
- 固定文字列: OYAUNIT="PC", KOUNIT="PC"
- 空欄項目: SIZEX, SIZEY, SIZEZ, NOTE, REVNOTE, REVDT, REVTANCD

**出力**: `M0850_品目構成マスタ.csv`

## ステップ4: 品目工程マスタ作成
**スクリプト名**: `03_create_item_process_master.py`

### 入力データ
- `14_品目工程work.csv` (ステップ2で作成)
- `M0410_工程マスタ.csv`
- **EJデータベース**: M_PUCH_UNIT_COST, M_ITEM テーブル

### 処理4-1: 工程マスタとの突合
**処理内容**:
- M0410_工程マスタ.csvを読み込んで有効KTCD一覧を作成
- 工程コード存在チェック用（現在はコメントアウト）

**中間データ**: 有効KTCD辞書（メモリ内）

### 処理4-2: EJシステムからの関連データ取得
**処理内容**:
- M_PUCH_UNIT_COSTテーブルから仕入先コード（VEND_CD）と購入単価（UNIT_COST）を取得
- M_ITEMテーブルからリードタイム（PUCH_FIXED_LT）を取得
- 最新日付優先で辞書を作成

**中間データ**: 
- SRCD辞書（メモリ内）
- SRPRICE辞書（メモリ内）
- LDTIME辞書（メモリ内）

### 処理4-3: M0840レイアウトへの変換
**処理内容**:
- 完成部番でグループ化してSEQ（1,2,3...）、KTSEQ（10,20,30...）を付与
- 前工程からKTCD抽出（最初のハイフンまで）
- 工程コード変換: "A0"→"AO", "PA1"/"PA2"→"PA"
- 前工程をキーとしてSRCD、SRPRICEを設定
- 完成部番をキーとしてLDTIMEを設定

**例外処理**:
- 特定品目（KS91-03006BA、KD64-00202BA）は処理対象外
- **PEFIN工程の特別処理**:
  - LDTIME = 0, SRPRICE = 0
  - CSBCD = "10" (通常は"13")
  - RCVTSTKBN = "2", RCVCHKKBN = "2" (通常は"1")

**固定値・条件値**:
- SGNCD, SUPCD = 空欄
- DDTIME = 0, SGTIME = 0
- CSBCD = "13" (PEFINの場合"10")
- SUPCLSCD = KTCDが"AO"の場合"6", その他"5"
- RCVTSTKBN = "1", RCVCHKKBN = "1" (PEFINの場合"2")

**出力**: `M0840_品目工程マスタ.csv`

## 重要な注意事項

### 処理順序
**必ず以下の順序で実行してください**:
1. `00_extract_krd_data.py`
2. `01_integrated_process.py`
3. `02_create_item_composition_master.py`
4. `03_create_item_process_master.py`

### フォルダ構成
- **input**: 元データファイル
- **work**: 中間ファイル（各処理で作成・使用）
- **output**: 最終マスタファイル
- **kensyou**: 検証用ファイル

### 中間ファイルの管理
- 各処理で作成される中間ファイルは次の処理で使用されます
- 処理完了後、不要な中間ファイルは自動削除される設定になっています

### データベース接続要件
- KRDデータベース（MySQL）: 製造実績データ取得用
- EJデータベース（Oracle）: 品目・仕入先・購入単価・リードタイム取得用
