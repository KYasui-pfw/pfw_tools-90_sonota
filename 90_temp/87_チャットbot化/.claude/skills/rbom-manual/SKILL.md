# rBOM操作説明書の検索

マニュアル全体（約80万文字）は大きすぎて一度に読めない。機能単位に分割済みなので、**必要な機能のファイルだけを読む**こと。

## 最初にやること: マニュアルの場所を探す

分割済みマニュアルは、**`manual/INDEX.md` があるフォルダ**。
- 作業フォルダ（Claude Code）または接続したフォルダ（Cowork）の直下にある `manual/` を、まず確認する。
- 無ければ、ファイル検索で `**/manual/INDEX.md` を探す。
- 見つからなければ、推測で答えず「マニュアルのフォルダ（manual/）が見つからない。作業フォルダかフォルダ接続を確認してほしい」と伝える。

以降の `manual/` はこのフォルダを指す。元PDF `V4.0_rBOM操作説明書.pdf` は、`manual/` と同じ階層にある場合がある（無くても検索・回答はできる）。

補足資料の過去の問合せ・課題は、**`qa/INDEX.md` があるフォルダ**（通常は `manual/` と同じ階層）。`qa/` が見つからなくても、マニュアルだけで答えてよい（その旨は伝えなくてよい）。

## 手順

1. **候補を絞る**（全文は読まない）
   - 機能名が分かる → `manual/INDEX.md`（部・章の一覧）→ 該当章の `_INDEX.md`（機能名・ページ・要約・キーワード）の順に見る。
   - 機能名が分からない → `manual/` 全体をgrep（文字列検索）する。質問の言葉をそのまま使わず、言い換えも併せて検索すること（例: 納期変更 → 納期|希望納期|日程変更、取消 → 取消|削除|キャンセル）。まず該当ファイル名と件数だけを見て、当たり過ぎる語は絞る。
   - 章の `_INDEX.md` の要約・キーワードも、候補選びに使う。
2. **該当する機能ファイルだけを読む**
   - 1ファイルが数万文字のものもある（手配指示入力・発注登録・品目マスタなど）。大きいファイルは行番号つきで検索し、必要な範囲だけ読む。
3. **参照先をたどる**
   - 本文中の「※詳細は『第3部 生産管理 第4章 購買管理 [11-02]発注登録』を参照」は、その機能のファイルへ移動する指示。回答に必要な場合だけたどる。
4. **回答する**
   - 手順・項目の意味はマニュアルの記述に沿って答え、**出典（機能名とPDFページ、例: 「受注手配指示入力 P184-188」）を付ける**。
   - マニュアルに書かれていないことは、推測で補わず「マニュアルには記載がない」と伝える。一般知識を足す場合は、そう分かるように区別する。
   - 自社の運用（社内のカスタマイズ・独自ツール等）はこのマニュアルの対象外。必要なら、下の「補足: 過去の問合せ・課題（qa/）」を確認する。

## 補足: 過去の問合せ・課題（qa/）の使い方

**主はあくまでマニュアル。** 最初から `qa/` を探さず、必ず先にマニュアルを調べて、回答の軸をマニュアルに置く。`qa/` は補助で、確認は軽く済ませる（検索は1〜2回、読むのは該当の数件まで）。

`qa/` は、福原つながるプロジェクトの課題管理表（問合せ・課題シート）のうち**回答済み（状況=完了）の分**を、1件1ファイルにしたもの。

**`qa/` を見るとき**（次のどれかだけ）
- マニュアルを調べても答えが見つからない、または記述があいまいで判断に迷うとき。
- 回答に、福原での実際の扱い・決定（運用、設定の理由など）の補足があると役立ちそうなとき。
- 利用者が `QA-〇〇`・`No.〇〇` や「前に同じ質問があったか」を尋ねたとき（この場合は `qa/` を調べる）。

**探し方**: `qa/INDEX.md` → `qa/問合せ/_INDEX.md`・`qa/課題/_INDEX.md`（機能名順の一覧）→ 1件ごとのファイル。ファイル名＝番号（問合せ `QA-6.md`、課題 `No.348.md`）。機能名が分からなければ `qa/` 全体をgrepする（言い換えも併せて検索）。

**回答への書き方**
- 本文はマニュアルの内容で書く。`qa/` の内容は、末尾に「補足（過去の問合せ）」として分けて書き、**シートと番号**（例: 「問合せ QA-6」「課題 No.348」）を出典に付ける。
- マニュアルだけで答えられるときは、`qa/` に触れない。
- マニュアルと `qa/` が食い違うときは、マニュアルの記述を先に示し、`qa/` は「福原での個別の回答・決定」として併記する。
- マニュアルに無く `qa/` にだけある内容で答えるときは、「マニュアルには記載がなく、過去の問合せでは〜とされている」と書く。
- 発生日・完了日が古い件は日付を添える（その後に仕様が変わった可能性がある）。

**注意**
- 仕掛中・未着手（未回答）の件は入っていない。見つからなくても、「該当の事例はない」とは言い切らない。
- 先頭に「補足シート」とある件は、元Excelに画面キャプチャ等の添付シートがある。内容は `qa/` に入っていない。
- 発信者・対処者は出していない。本文の「○○」は氏名を伏せたもの。復元・推測はせず、誰が回答したかには答えない。

## 画面図が必要なとき

本文はテキストのみ。画面レイアウトやボタン配置を確認したい場合は、ファイル冒頭の「PDFページ」または本文中の `<!-- P184 img=3 -->`（ページ番号と画像数）から、元PDFの該当ページを特定する。
- PDFが手元にあり、ページ単位で読める手段があれば、必要なページだけを読む（数ページずつ。全体は読まない）。
- 読めない・PDFが無い場合は、**ページ番号を伝えて、利用者に原本のそのページを開いてもらう**。

## 注意

- 本文は文字を正規化済み（半角カナ→全角、⽀・⼿などの康熙部首→通常の漢字）。検索は通常の漢字で書く。
- 機能名の `OP` はオプション機能（契約外だと画面がない）。
- 「章の扉」ページ（部・章のタイトルだけのページ）は分割データに含めていない。
- 分割・索引の作り直しは、元の開発フォルダにある `build_manual.py`（マニュアル）と `build_qa.py`（過去の問合せ。元Excelが必要）で行う（管理者の作業。このskillの利用には不要）。
