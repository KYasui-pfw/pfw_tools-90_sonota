# RPA化 注意事項

内作工程チェック「簡易マスタ未登録（SEINOなし）」の品目を抽出し、rBOM の品目工程マスタに MCKR 工程を登録する RPA。
RPA サーバー **esrv10** で動かす。

## ファイル

| ファイル | 内容 |
|---|---|
| `01_未登録品目抽出.bat` | 実行用。同じフォルダの同名の `.ps1` を PowerShell 5.1 で実行する |
| `01_未登録品目抽出.ps1` | 本体（夜間処理の確認 → 抽出 → CSV 出力 → RPA） |
| `config.ini` | psql.exe の場所・Postgres のパスワード・起動するプログラム・ログイン情報 |
| `抽出結果.csv` | 抽出結果（毎回上書き） |
| `02_手配指示登録.bat` / `.ps1` | 「rBOMにのみ存在」のうち SEINO あり・KTCD_CHECK 空欄の「品目CD＋製番」を抽出（RPA 部分は未作成）。KRD は 01 と同じく Django 品目工程マスタ（PostgreSQL）を見る |
| `02_抽出結果.csv` | 02 の抽出結果（毎回上書き。列: SEINO, HMCD, HMNM, LISTNO） |
| `エラーログ.txt` | エラーの記録（追記していく） |

⚠ `config.ini` にはパスワードが書いてある。git にコミットしない（`.gitignore` に入れる）。

## 動きの流れ

1. **夜間処理の確認**: `http://rbom-yakan/yakan.csv` の1列目が `5`（夜間処理終了）のときだけ先へ進む。待たずに、起動時に1回だけ見る
2. **抽出**: rBOM（FastAPI `/query`）と Django の品目工程マスタ（PostgreSQL、psql 経由）から対象の品目を集め、`抽出結果.csv` に出す。**0件なら RPA は起動せずに終わる**
3. **RPA**: DLRUN.exe 起動 → ログイン → 品目工程マスタを開く → 品目ごとに登録 → 終了処理 → rbom.exe が残っていれば強制終了

## 終了コード

| コード | 意味 | bat |
|---|---|---|
| 0 | 正常終了／夜間処理が終わっていない／抽出0件（いずれも何もしないで終わった） | 閉じる |
| 1 | 想定外のエラー（API・DB の失敗など） | `pause` で止まる |
| 2 | RPA の途中で画面が見つからず、終了処理をして終わった | 閉じる |
| 3 | 夜間処理の状態が取れず、実行しなかった | 閉じる |

2・3 はエラーログに記録される。

## esrv10 でキー操作をするときの注意（ほかのスクリプトにも当てはまる）

### SendKeys を使わない
- **PowerShell（.NET）の `SendKeys` は、esrv10 ではキーが二重に入ったり抜けたりする。** TAB 8回が9回になる、F6 が2回押される、など回数がランダムにずれる
- 原因: 管理者権限で動くと、SendKeys は古い「ジャーナル再生」でキーを送る。これが不安定
- **管理者でない開発PCでは別の送り方になるので再現しない。開発PCの試験では見抜けない**
- 対策: Windows に直接「押す → 30ms → 離す」を送る（`keybd_event`）。このスクリプトの `RpaWin32.Press` / `RpaWin32.Type` をそのまま流用できる
  - 矢印・Insert・Delete・Home・End・PageUp・PageDown には「拡張キー」の印（`KEYEVENTF_EXTENDEDKEY`）を付ける。付けないとテンキーと取り違えられる
  - 文字は `VkKeyScan` で押すキーと Shift の要否を割り出して1文字ずつ送る（`#` → Shift＋3）
  - ALT 単独は SendKeys では押せない（`%` は次のキーと組み合わせる用）が、この方法なら押せる

### キーは「いちばん手前の画面」に届く
- 実行中はリモートデスクトップの画面に触らない。画面を切り替えるだけでも、リモートデスクトップが Shift・Ctrl・Alt・Tab の「離す」を送ってくる
- 操作する画面はタイトルで探してアクティブにしてから送る。見つからなければ止める（別の画面にパスワードなどを打ち込まないため）
- プロセス番号では画面をつかめないことがある。DLRUN.exe は rbom.exe を起動してすぐ終わるので、DLRUN のプロセス番号の画面は存在しない
- 日本語入力（IME）がオンだと、送った文字が変換されることがある

### rBOM の作り
- rbom.exe（説明: realtime BOM product/sale system、32ビット）は PowerBuilder 製・MDI。品目工程マスタなどの画面は別ウィンドウにならず、本番環境の画面のタイトル末尾に `[品目工程マスタ ID : w_bu8400]` のように付く
- 終了処理で閉じきれないことに備え、最後に rbom.exe を**名前で全部**強制終了している。⚠ 手で開いた rBOM も巻き込む

### TAB で届かないボタンを押す（画像判定・決め打ち座標を使わない）
- rBOM の画面上部のボタン列（指示・ﾌｨﾙﾀｰ・BOM追加・BOM修正 など）は、Windows の普通のボタン部品（クラス `Button`、表示文字＝ボタンの文字）になっている。**文字で部品を探し、その場で位置を取ってクリックできる**（2026-10-09、手配指示入力の「BOM追加」で開発PCにて確認。子画面が開いた）
- 手順
  1. スクリプトの最初で `SetProcessDPIAware()` を呼ぶ（呼ばないと拡大率 100% 以外の画面で座標がずれる）
  2. 対象の画面をタイトルで探して手前に出す（`SetForegroundWindow`。直前に ALT を1回押すと通りやすい）
  3. `EnumChildWindows` で子部品を列挙し、クラス `Button`・表示中・文字が完全一致のものを探す。見つからなければ止める
  4. `GetWindowRect` で範囲を取り、中心を計算する
  5. クリック直前に `WindowFromPoint(中心)` がそのボタンかを確かめる（ほかの画面が重なっていれば止める）
  6. `SetCursorPos` → `mouse_event` で左ボタン「押す → 30ms → 離す」
- ボタンの文字は半角カナのものがある（`ﾌｨﾙﾀｰ`、`納入先ﾁｪｯｸ`）。完全一致で探すときは半角で書く
- 座標を使わない代わりの方法: ボタンに `BM_CLICK`（0x00F5）を送る。マウスを動かさず、重なっていても押せる（未試験）
- 部品の一覧は `GetClassName` と `WM_GETTEXT` で取れる。一覧表（`pbdw`＝DataWindow）の中のセルは部品として取れない
- ⚠ 画面 ID で区別すること: 手配指示入力（`w_ju0100_pfw_cst`、MDI の中）で BOM追加 を押すと、**タイトルに同じ「手配指示入力」を含む**子画面 `手配指示入力【BOM追加】 ID : w_ju0120_pfw_cst` が**MDI の外の独立したウィンドウ**として開く。「手配指示入力」を含む、で探すと親子を取り違える

### キーがずれたときの調べ方
- PC全体のキー入力を記録する仕組み（低レベルキーボードフック `WH_KEYBOARD_LL`）を一時的に入れて調べた。解決後に外したので、また調べるときは作り直す
- 作るときの要点:
  - 見張りは**専用のスレッドで `GetMessage` を回す**。RPA の `Start-Sleep` と同じスレッドだと応答できず、PC全体のキー入力が遅れる
  - 送り主は `LLKHF_INJECTED`（0x10）の印で区別できる（プログラムが送ったもの／リモートデスクトップからのもの）
  - パスワードが残らないよう、ログイン入力のあとから記録を始める

## PowerShell の注意

- `.ps1` は **UTF-8（BOM付き）** で保存する。BOM が無いと PowerShell 5.1 で日本語が化ける
- `.bat` は **Shift-JIS・CRLF** で保存する。bat の中に日本語のファイル名を書くと cmd のコードページで化けるので、ps1 は bat 自身の名前から組み立てている（`%~dpn0.ps1`）。**bat と ps1 の名前は必ずそろえる**
- 変数名は大文字小文字を区別しない（`$chunk` と `$CHUNK` は同じ変数）
- PowerShell 7 で動かす場合
  - `Invoke-RestMethod` は JSON の日付文字列を日付型に変える（5.1 は文字列のまま）。そのまま文字にすると形が変わり、日付の比較が崩れる
  - `Add-Type` に `-ReferencedAssemblies` を付けると標準の部品が読み込まれなくなる
