# EJ-rBOM マッピング処理

## 1. 概要

旧EJシステムと新rBOMシステムの発注残データを突合し、対応関係をマッピングする。

---

## 2. データソース

### EJシステム
| 項目 | テーブル.カラム |
|------|----------------|
| 発注番号 | T_RLSD_PUCH_ODR.PUCH_ODR_CD |
| 品目コード | T_RLSD_PUCH_ODR.ITEM_CD |
| 数量 | T_RLSD_PUCH_ODR.PUCH_ODR_QTY |
| 納期 | T_RLSD_PUCH_ODR.PUCH_ODR_DLV_DATE |

| 品目コード | D3340.HMCD |
| 数量 | D3340.THQTY |
| 納期 | D3340.DRVDT |

## 3. マッピング処理順序

| 順序 | 処理 | EJ側 | rBOM側 | 結果 |
|:----:|------|------|--------|------|
| 1 | 手動マッピング | 発注番号 | 発注番号+行番号 | ステータス「手」 |
| 2 | 固定マッピング | （固定済みを後続処理から除外） | | |
| 3 | 受入済みマッピング | 発注番号 | D3360.NOTE内のEJ発注番号 | ステータス「済」+★ |
| 4 | 自動マッピング | 品目コード + 納期（未使用） | 品目コード + 納期（未使用） | ステータス「済」 |
| 5 | 備考マッピング | 品目コード + 納期（未使用） | MK020.NOTE + 納期（未使用） | ステータス「済2」 |
| 6 | 未マッピング | （マッチなし） | | ステータス「未」 |

1.手動マッピング
EJ発注番号とrBOMマッピングは自動処理にかける前に必ずマッピングさせるという組み合わせが対象
手動マッピング用のテーブルを参照して、マッピングする

2.固定マッピング
自動マッピング後、これが正と考えられるマッピングを固定する
固定されている組み合わせは、自動マッピング前に優先マッピングとなる
※数日に分けて、複数回のマッピング処理を実行することが必要になったため、追加された処理

3.構成に不足がある段階で受け入れ処理が行われてしまい、それを正とするしかなくなっている組み合わせ
※本当なら正しい構成になるまで受け入れてはいけなかった

4.自動マッピング
EJとrBOMの"品目コード"でのマッピング処理　納期のマッピングをすると一致しない率が大きくなるため、納期のマッピングはしない
- 納期・数量が違ってもマッピングする
- 数量が違う場合は分割することもある 以下のケース
  - 品目：AAAAA　で　EJ発注番号：E00001111　が10個、E00002222　が6個
  - 品目：AAAAA　で　rBOM発注番号：000003456+001　が4個、000004567+001　が8個、000005678+001　が5個
    - E00001111 4個 と 000003456+001 4個 がマッピング
    - E00001111 6個 と 000004567+001 6個 がマッピング
    - E00002222 2個 と 000004567+001 2個 がマッピング
    - E00002222 4個 と 000005678+001 4個 がマッピング
    - 000005678+001 1個 が未マッピング

5.備考マッピング
マッピング処理2週目　1週目後、未マッピングのデータが対象
工程発注の考え方がEJとrBOMで異なるため、MK020の備考（NOTE）に、EJの工程発注の品目コードを入れているケースがある
2週目では、EJの品目コードと、MK020のNOTEで比較する

6.未マッピング
1~5の処理から漏れたものが未マッピングです
