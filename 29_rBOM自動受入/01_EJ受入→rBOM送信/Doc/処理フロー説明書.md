# EJ受入データ → rBOM送信 処理フロー

旧システム（EJ）の受入実績を、新システム（rBOM）に自動転送するツールです。

---

## 01_EJ受入データ変換.py

| 項目 | 内容 |
|------|------|
| インプット | EJデータベース（T_ACPT_RSLT + T_RLSD_PUCH_ODR） |
| 処理 | EJから2025/12/1以降の受入実績を抽出 |
| アウトプット | `01_EJ受入データ.csv` |

---

## 02_送信データ作成.py

| 項目 | 内容 |
|------|------|
| インプット | `01_EJ受入データ.csv`、`mapping.db` |
| 処理 | EJ発注番号とrBOM発注番号を突き合わせ、送信用データを作成 |
| アウトプット | `02_送信データ全件.csv`（マッピング成功）|
|  | `02_マッピングDBに発注番号無し.csv`（対応表に無い）|
|  | `02_rBOMに発注無し.csv`（rBOM側に発注が無い）|

---

## 03_送信データフィルタリング.py

| 項目 | 内容 |
|------|------|
| インプット | `02_送信データ全件.csv`、rBOM API（D3350、D3340） |
| 処理 | 既に登録済み・完納済みのデータを除外 |
| アウトプット | `03_送信データ.csv`（送信対象）|
|  | `03_除外データ.csv`（受入済み or 完納/強制完納）|
|  | `03_除外データ（要チェック）.csv`（一部完納）|

**除外条件**
- D3350.NOTEに一致 → 受入済みのため除外
- D3340.STATUS=4or8 → 完納/強制完納のため除外
- D3340.STATUS=3 → 一部完納として要チェックへ

---

## 04_rBOM受入送信.py

| 項目 | 内容 |
|------|------|
| インプット | `03_送信データ.csv` |
| 処理 | rBOM受入API（POST /acceptance/）に送信 |
| アウトプット | rBOMへ登録 |

※03_送信データ.csv　をrBOMの中間テーブルに書き込む処理です
